# Deadlock chat: input, capture, OCR — citable facts

Scope: can a Windows tool read *Deadlock* text chat and type replies? Every claim is linked; **[UNCONFIRMED]** marks speculation or unverifiable items. Verified 2026-09-12.

## 1. How Deadlock text chat works

- **Enter = team chat, Shift+Enter = all chat**, both remappable in Settings → Hotkeys; the hero is inactive while the chat box is open ([Hawk Live](https://hawk.live/posts/how-to-use-text-and-voice-chat-deadlock)).
- **Chat is not only a corner panel.** Messages render as world-space bubbles at the speaker: *"nothing shows under their character… I have to press enter to look into the chat history"* ([bug report](https://forums.playdeadlock.com/threads/invisible-text-chat-bug.118272/)). Bubble area overlaps voice icons and mis-scales at 4K ([thread](https://forums.playdeadlock.com/threads/chat-ping-bubbles-covered-at-4k-resolution.156697/)). ⇒ OCR must capture the **opened chat pane (Enter)**, not a static bottom-left strip.
- **Fonts/locale:** the game is English-only; Cyrillic renders with huge letter spacing (font-metrics bug, [thread](https://forums.playdeadlock.com/threads/cyrillic-font-in-chat-with-large-spaces-between-letters.8056/)). Typing Chinese through an IME in the chat box **crashed the game** (2024-07 report linking `SDL_windowskeyboard.c`, [thread](https://forums.playdeadlock.com/threads/ime-input-method-editor-support.10609/)) ⇒ chat text entry is SDL2-based, i.e. text arrives as `WM_CHAR`/`SDL_TEXTINPUT` [inference from that report].
- **Developer console exists:** enable "Dev command console", press **F7**; `-console -exec autoexec` + `autoexec.cfg` autoloads commands; cheat cvars need `sv_cheats`; console usable in Hideout/Sandbox/Explore NYC/cheat-enabled customs ([Deadlock Wiki](https://deadlock.wiki/Console_commands)).
- **On-disk logs:** crash/console logs live in `\Deadlock\game\bin\win64` ([forum](https://forums.playdeadlock.com/threads/where-are-the-crash-logs.86726/)). No chat-log file is documented. **Decision-critical unknown: whether Deadlock honours `-condebug` and prints chat to `console.log`.** In CS2 this is proven — two translators tail `console.log` ([CS2-Translator](https://github.com/ParadoxLeon/CS2-Translator), [cs_translate](https://aur.archlinux.org/packages/cs_translate)) — but Valve's Deadlock cvar list is bot-protected and could not be checked. **[UNCONFIRMED]**

## 2. Paste, length limits, non-ASCII

- No primary source shows CS2/Deadlock in-game chat accepting **Ctrl+V**. "Auto paste in CS2 chat" guides implement it as a console keybind `bind <key> "say <message>"` ([cs2pulse](https://cs2pulse.com/how-to-auto-paste-in-cs2-chat/)); `say`/`say_team` are documented CS2 commands ([csgo-nade](https://csgo-nade.com/commands/chat/say), [totalcsgo](https://totalcsgo.com/commands/say)). ⇒ chat-box paste: **[UNCONFIRMED], leaning unsupported**; the documented paste-friendly path is the **console** (guides tell users to copy a generated command and paste it there — inference, not a Valve statement).
- A Panorama chat clipboard path exists but was bugged on Linux in CS:GO lobby chat ([csgo-osx-linux#642](https://github.com/ValveSoftware/csgo-osx-linux/issues/642) — existence only, body unretrievable).
- **Length limit:** none documented for Source 2. Source 1 chat passes raw chars incl. space/newline — an acknowledged exploit class ([Source-1-Games#4061](https://github.com/ValveSoftware/Source-1-Games/issues/4061)). Deadlock chat flooding currently **crashes lobbies and got players banned** ([thread](https://forums.playdeadlock.com/threads/game-crash-exploit-via-chat-flood-match-id-104220539.160983/)) ⇒ rate-limit any auto-send.
- **Non-ASCII:** CS2 fonts lack full CJK coverage; Chinese players patch fonts to fix missing glyphs/clipping ([Bilibili guide](https://www.bilibili.com/video/BV1adRMB7ExQ/)), and CS2 does not render the Microsoft Pinyin candidate window in-game ([MS Q&A](https://learn.microsoft.com/zh-cn/answers/questions/4008322/cs2)). Consistent with Deadlock's Cyrillic bug + IME crash. **[UNCONFIRMED]** that this holds for every CS2/Deadlock build.

## 3. Synthetic keyboard input

- `SendInput` is current; `keybd_event` is superseded ([MS](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput), [MS](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-keybd_event)). Synthetic input "goes through the input system like hardware input" yet is detectable via `LLKHF_INJECTED` (bit 4 = 0x10) ([Chen, 2025](https://devblogs.microsoft.com/oldnewthing/20250319-00/?p=110979), [KBDLLHOOKSTRUCT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-kbdllhookstruct)).
- `pyautogui`'s Windows backend uses **keybd_event**, not SendInput ([source](https://github.com/asweigart/pyautogui/blob/master/pyautogui/_pyautogui_win.py)); `keyboard.write` sends unmappable characters via **SendInput + `KEYEVENTF_UNICODE`** ([source](https://github.com/boppreh/keyboard/blob/master/keyboard/_winkeyboard.py)) — the only route that types Chinese without an IME (it lands as `WM_CHAR` [inference]).
- Real-world failure mode: text typed but the chat-opening **Enter was ignored until 100 ms sleeps** were added ([SO](https://stackoverflow.com/questions/65877459/sendinput-fails-to-send-enterkey-to-specific-program)). Whether Raw Input (`WM_INPUT`) games see SendInput is undocumented by Microsoft ([About Raw Input](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-raw-input), [SO](https://stackoverflow.com/questions/35408495/sendinput-to-background-window)). No Deadlock/CS2-specific test exists — **[UNCONFIRMED]**.
- **VAC:** official VAC pages are JS/bot-gated and unreadable ⇒ no official quote. Trusted Mode (CS:GO/CS2) blocks third-party software from *interacting* with the game and blocks OBS game-capture hooking ([HLTV patch notes](https://www.hltv.org/news/29963/trusted-mode-goes-live-in-latest-csgo-update), [OBS forum](https://obsproject.com/forum/threads/capture-cs2-with-anti-cheat.182477/)). VACNet 3.0 reportedly began banning AHK bunny-hop scripts ([DRAFT5, 2024](https://draft5.gg/noticia/anti-cheat-da-valve-comecou-a-detectar-cheat-para-bunny-hop)) — gameplay advantage, not chat; **[UNCONFIRMED]** officially. Userspace `WH_KEYBOARD_LL` hooking: no source classifies it as VAC-detectable — **unknown** (kernel Interception driver is refused by some EAC/Vanguard builds, [pyinterception](https://github.com/kennyhml/pyinterception)). The `keyboard` library warns games "may register hooks that swallow all key events" ([README](https://github.com/boppreh/keyboard#known-limitations)).

## 4. Region capture at 2–5 fps

- **WGC:** `windows-capture` 2.0.1 (MIT, win_amd64, Python ≥3.9), window-item capture with `minimum_update_interval` throttle ([PyPI](https://pypi.org/project/windows-capture/), [MS](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture.graphicscapturepicker?view=winrt-28000)).
- **DXGI Desktop Duplication** duplicates an *output*, not a window; `AcquireNextFrame` returns `DXGI_ERROR_ACCESS_LOST` on mode change or "other full-screen application" ([MS](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/idxgioutputduplication-acquirenextframe)). `dxcam` (DXGI+WinRT) claims stable exclusive-fullscreen capture, 239 fps @1080p ([README](https://raw.githubusercontent.com/ra1nty/DXcam/master/README.md)) — vendor claim. `bettercam` stuck at 1.0.0 (2023-11) ([PyPI](https://pypi.org/project/bettercam/)); `d3dshot` unmaintained.
- **GDI:** `mss` 10.2.0 (MIT, ctypes BitBlt, [PyPI](https://pypi.org/project/mss/)); `PrintWindow` (+ undocumented `PW_RENDERFULLCONTENT = 0x2`) is the documented background path, ~80 ms/call ⇒ ~12 fps ceiling ([MS](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-printwindow), [SO](https://stackoverflow.com/questions/77182962/increase-speed-performance-on-c-printwindow-in-powershell), [SO](https://stackoverflow.com/questions/51119033/render-chrome-with-printwindow)).
- **Black frames:** one confirmed case — DXGI duplication returned all-zero frames under RDP on NVIDIA/Win11 while WGC worked ([MS Q&A](https://learn.microsoft.com/en-au/answers/questions/1920987/idxgioutputduplication-acquirenextframe()-gives-bl)). Exclusive-fullscreen / hybrid-GPU black frames: vendor claims only — **[UNCONFIRMED]**. Practical: borderless windowed is the only mode where all three paths are known-good.

## 5. OCR options (short, light-on-dark UI text, CPU)

| Option | Version / license | Notes |
|---|---|---|
| `Windows.Media.Ocr` via **winocr** | 0.0.15, MIT ([PyPI](https://pypi.org/project/winocr/)) | Built into Win10+; needs the OCR language capability pack; ~48 s per 1000 images on 1 core, 16 s on 4; no GPU ([MS](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine?view=winrt-28000)) |
| **RapidOCR** `rapidocr` | **3.9.2** (2026-07-21), Apache-2.0 ([PyPI](https://pypi.org/project/rapidocr/)) | 27.3 MB wheel **bundles small det+cls+rec ONNX models**; onnxruntime default, no longer a hard dep; legacy `rapidocr_onnxruntime/_openvino/_paddle` names retired ([docs](https://rapidai.github.io/RapidOCRDocs/main/install_usage/rapidocr/install/)). Best CPU fit for one-line text |
| **PaddleOCR** | **3.7.0** (2026-06-11), Apache-2.0 ([PyPI](https://pypi.org/project/paddleocr/)) | Current gen **PP-OCRv6**: tiny 1.5M / small 7.7M / medium 34.5M params; vendor-claimed +4.6% det, +5.1% rec vs PP-OCRv5_server, 5.2× CPU speedup (OpenVINO); 146.8 kB wheel ⇒ models fetched on first run; needs PaddlePaddle |
| **Tesseract** + pytesseract | 5.5.3 / 0.3.13, Apache-2.0 ([PyPI](https://pypi.org/project/pytesseract/)) | Expects **dark-on-light ≥300 DPI**, `--psm 7` for one line ⇒ invert+upscale game UI ([tessdoc](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html)); `tesserocr` 2.11.0 ships no Windows wheels |
| **EasyOCR** | 1.7.2 (2024-09), Apache-2.0 ([PyPI](https://pypi.org/project/easyocr/)) | PyTorch dependency; heaviest CPU cost — least suited at 2–5 fps |

No published benchmark measures any of these on small light-on-dark game-chat lines — accuracy expectations are **[UNCONFIRMED]**.

## 6. Existing chat-translation tools

- **CS2 (log-based, no injection):** [ParadoxLeon/CS2-Translator](https://github.com/ParadoxLeon/CS2-Translator) (C#, reads console output with `-condebug`, Google Translate; parent project archived); [cs_translate](https://aur.archlinux.org/packages/cs_translate) (Node CLI tailing `console.log`, MIT).
- **Dota 2:** [DotATranslator](https://github.com/ur0/DotATranslator) (**EasyHook DLL injection** back into the chat pane, archived 2017, broke each patch); [GameChatTranslator](https://github.com/WatcherApps/GameChatTranslator) (**Tesseract OCR of the Dota chat box** + click-through overlay, 18★, pushed 2025-02, no license).
- **Generic overlay OCR:** [Translumo](https://github.com/ramjke/Translumo) (Windows OCR/Tesseract/EasyOCR; needs borderless), [LunaTranslator](https://github.com/HIllya51/LunaTranslator), [Textractor](https://github.com/Artikash/Textractor) (VN hooking), [MORT](https://github.com/kmonkeyhead/MORT).
- **Deadlock-specific: none for chat.** Only [ChatLane](https://github.com/RedMser/ChatLane) (chat-wheel editor) and [Deadlock-Translate-Helper](https://github.com/hisacat/Deadlock-Translate-Helper) (UI-localisation files). [deadlock-api](https://github.com/deadlock-api) is match/stats only — no live chat endpoint.

## 7. Risk notes

- **Screen reading:** no source documents a VAC/EAC/BattlEye/Vanguard ban for OCR or screen capture; Vanguard itself screenshots. Absence of evidence, **not** proof of safety.
- **Interaction is the sharper edge:** Trusted Mode blocks third-party interaction and hook-based capture ([HLTV](https://www.hltv.org/news/29963/trusted-mode-goes-live-in-latest-csgo-update), [OBS](https://obsproject.com/forum/threads/capture-cs2-with-anti-cheat.182477/)). Steam's appdetails for Deadlock (1422450) lists no anti-cheat field and no Trusted Mode ([API](https://store.steampowered.com/api/appdetails?appids=1422450)); 2024 reporting said no anti-cheat at launch ([gameland.gg](https://gameland.gg/everything-to-know-about-deadlocks-anti-cheat-system-vac-status/)) — both **[UNCONFIRMED]** for the current build.
- **Chat conduct bans are real:** CS2 communication penalties ([Steam Support](https://help.steampowered.com/ja/faqs/view/3E8D-FA11-0704-C0CD)); Deadlock players banned over the chat-crash exploit; guides warn spam-binding chat gets you reported for griefing ([cs2pulse](https://cs2pulse.com/how-to-auto-paste-in-cs2-chat/)).

**Bottom line:** the only proven Valve route to chat text is the `-condebug` console log (CS2). For Deadlock, verify empirically whether chat lands in `console.log`; if not, OCR the **opened chat pane** (Enter) — never type via IME (crash risk), use SendInput + `KEYEVENTF_UNICODE` with per-key delays, rate-limit sends, and prefer RapidOCR 3.9.2 or Windows OCR.
